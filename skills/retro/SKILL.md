# /retro — разбор сессии

Сессия, которая стоила втрое дороже соседних, почти всегда буксовала: перечитывала одни и те же
файлы, билась об отказы прав, получала от пользователя «не то». Скилл находит эти потери по
транскрипту и переводит их в одну-три правки правил. Правила сам не меняет.

**Правило дешевизны: транскрипт в контекст целиком не читать.** Файл сессии — мегабайты; в
контекст попадают только счётчики и короткие цитаты из `jq`-выборок ниже. `Read` по jsonl — запрещён.

## Шаг 1. Vault

`AGENTS.md` в cwd → `vault`. Если хук SessionStart уже дал `PROJECT_RESTORE`, файл не читать.

## Шаг 2. Выбрать сессию

```bash
python3 ~/.claude/skills/tokens/token-stats.py --by session --since $(date -d '7 days ago' +%F) --json \
  | jq -r '.rows | sort_by(-.cost) | .[:5][] | "\(.name[:8])  $\(.cost|.*100|round/100)  \(.phases|map(.[0])|join(","))"'
```

- Аргумент — id: взять строку с этим префиксом. Аргумент — слаг: добавить `--task <KEY>`
  (ключ Jira из слага) и взять самую дорогую.
- Без аргумента — показать пять строк и **ждать выбора**; самую дорогую предложить по умолчанию.

Путь к транскрипту: `ls ~/.claude/projects/*/<id>*.jsonl` (id полный — из `.name`). Проекту он
принадлежит по имени каталога. Рядом положить `T=<путь>`.

## Шаг 3. Признаки буксования

Каждая выборка печатает число и до 10 строк. Запускать все, даже если первая уже «всё объяснила».

```bash
# повторные чтения одного пути (Read / Grep / Glob)
jq -r 'select(.type=="assistant") | .message.content[]? | select(.type=="tool_use")
  | select(.name=="Read" or .name=="Grep" or .name=="Glob") | .input.file_path // .input.path // .input.pattern' "$T" \
  | sort | uniq -c | sort -rn | awk '$1>1' | head

# ошибки инструментов и отказы прав
jq -r 'select(.type=="user") | .message.content[]? | select(.type=="tool_result" and .is_error==true)
  | (.content | if type=="array" then map(.text? // "") | join(" ") else tostring end)[:160]' "$T" \
  | sort | uniq -c | sort -rn | head

# прерывания пользователем
jq -r 'select(.type=="user") | .message.content | if type=="string" then . else map(.text? // "") | join(" ") end' "$T" \
  | grep -c '\[Request interrupted'

# реплики-исправления: «не то», «не так», «я же», «зачем», «откати», «верни»
jq -r 'select(.type=="user") | .message.content | if type=="string" then . else map(.text? // "") | join(" ") end' "$T" \
  | grep -iE '^(не то|не так|нет[,.]|я же|зачем|откати|верни|стоп|хватит)' | cut -c1-160 | head

# откаты правок
jq -r 'select(.type=="assistant") | .message.content[]? | select(.type=="tool_use" and .name=="Bash") | .input.command' "$T" \
  | grep -E 'git (checkout --|restore|reset|stash)' | head

# самые частые инструменты и число ответов модели — масштаб сессии
jq -r 'select(.type=="assistant") | .message.content[]? | select(.type=="tool_use") | .name' "$T" | sort | uniq -c | sort -rn
jq -r 'select(.type=="assistant") | .message.id' "$T" | sort -u | wc -l
```

Если у задачи есть `<vault>/notes/handoff-<slug>.md` — прочитать раздел «Тупики»: там уже
записано, что не сработало и почему.

## Шаг 4. Разбор

Из выборок выбрать **топ-3 потери шагов** — по числу лишних вызовов, а не по яркости. Для каждой:

1. **Симптом** — цифра и цитата из выборки («`Read` одного файла 6 раз», «3 отказа на `curl`»).
2. **Причина** — чего агенту не хватало: факта о проекте, правила, запрета, инструмента.
3. **Правило и адрес** — куда класть, по убыванию локальности:
   - `AGENTS.md` проекта — факт о проекте (команда запуска, где лежит X, конвенция);
   - `agents/{research,plan,implement}.md` в devflow — поведение фазы;
   - `~/.claude/devflow-instructions.md` — конвенция для всех проектов;
   - хук в `~/.claude/hooks/` или `settings.json` — когда текста недостаточно и нужен запрет/подсказка машиной.
4. **Предлагаемый текст** — одна-три строки, готовые к вставке, в стиле файла-адресата.

Не предлагать правило, под которое есть один случай: один раз — шум, трижды — паттерн. Если
потерь нет (дорогая, но ровная сессия) — так и написать, без выдуманных правок.

## Шаг 5. Показать и записать

Показать пользователю таблицу «потеря → правило → адрес → текст» и записать
`<vault>/notes/retro-<id8>.md` (для слага — `retro-<slug>.md`):

```markdown
---
created: YYYY-MM-DD
project: <project>
type: retro
session: <полный id>
task: <KEY или —>
tags: [retro, <задача>]
---

# Ретро сессии <id8> — <YYYY-MM-DD>

Стоимость $N, ответов модели N, инструментов N. Задача: <KEY / тема>.

## Что стоило лишних шагов
1. <симптом с цифрой> — <причина>
...

## Какое правило поменять
| Файл | Место | Предлагаемый текст |
|------|-------|--------------------|

## Решение пользователя
<принято / отклонено / отложено — по каждой строке, заполняется после ответа>
```

Спросить: «Применить какие из правок?» Файл правила править **только после явного «да»** по
конкретной строке; после правки вписать решение в заметку. Молчание или «потом» — заметка
остаётся с «отложено».

## Чего не делать

- Не читать jsonl через `Read` и не делать `cat` по нему — только выборки выше.
- Не править `AGENTS.md`, агентов, глобальные инструкции и хуки без «да».
- Не коммитить и не пушить: правка правила — изменение в рабочем дереве, публикует пользователь.
- Не разбирать две сессии за раз: паттерн ищется по одной, подтверждается следующим `/retro`.
