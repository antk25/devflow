# /smoke — сценарий в браузере, вердикт в ответе

Сырые снимки, сеть и консоль остаются в этом подагенте; вызвавший получает таблицу вердиктов.
Формат ответа и правила безопасности — в агенте `browser`; здесь — как проверять.

## 1. Аргументы
Строка вызова: `$ARGUMENTS`

Формат: `env: <имя>; slug: <slug>; save; <сценарий>`. Разбирать `scenario` по сегментам через `;`:
ведущие сегменты `env:` / `slug:` / `save` в любом порядке снимаются, первый иной сегмент — начало
сценария (дальше `;` — уже его текст). Ни одна форма не начинается с `--`: такие аргументы форк теряет.
- `env: <имя>` — окружение из раздела «Browser» `AGENTS.md`; по умолчанию `local`.
- `slug: <slug>` — каталог артефактов `/tmp/devflow-smoke/<slug>/`; по умолчанию `adhoc`.
- `save` — закрепить сценарий скриптом (нужен `slug:`, иначе «не хватает slug»).

## 2. Окружение
Прочитать `AGENTS.md` в cwd. Раздел `## Browser` → подраздел `### <env>`:
```
- Адрес: <базовый адрес или шаблон с тенантом>
- Вход: нет | пароль витрины (`@env:ИМЯ`) | токен в localStorage (команда получения) | форма email+пароль (`@env:ИМЯ`, `@env:ИМЯ`)
- Флаги: --insecure (если нужен)
- Ограничения: только чтение / что не трогать
```
Из окружения берутся адрес, способ входа, флаг `--insecure` и ограничения; сценарий их дополняет
(тенант, путь, параметры). Адрес в сценарии с хостом, которого нет ни в одном окружении, — пометка
`вне окружений: <хост>` в строке вердикта; тогда способ входа должен быть назван в сценарии явно
(`вход: нет` тоже годится). Заготовка в угловых скобках (`<адрес>`) — адреса нет.

## 3. Полнота — до запуска браузера
Нужны адрес и способ входа (из окружения или сценария) и хотя бы одна проверка. Чего-то нет →
ответ только с разделом «Не хватает» («не хватает адреса и способа входа», «не хватает переменной
`@env:ИМЯ` в описании окружения», «нет раздела Browser в AGENTS.md, окружение `<env>`»); браузер не
запускать, `devflow-browser start` не вызывать.

## 4. Прогон
```bash
mkdir -p /tmp/devflow-smoke/<slug>
S=$(devflow-browser start [--insecure] --task <slug>)   # один раз; в конце обязательно stop;
                                                  # --task ведёт метку активности: вызвавший видит, что прогон жив
devflow-browser $S new_page "<адрес>"            # открывает вкладку 2
… проверки …
devflow-browser $S stop
```
Вход по способу окружения, до проверок:
- `нет` — сразу к проверкам.
- пароль витрины — `new_page` на `/password`, `take_snapshot 2` ради `uid` поля, `click 2 <uid>`,
  `type_text 2 "@env:ИМЯ" --submitKey Enter`; признак — URL после отправки не `/password`.
- токен в `localStorage` — команда получения из окружения, затем
  `evaluate_script '() => localStorage.setItem("accessToken", "@env:ИМЯ")' --pageId 2`, `navigate_page 2 --type reload`.
- форма email+пароль — открыть адрес входа, `take_snapshot 2`, по очереди `click` + `type_text`
  для каждого поля, отправка `--submitKey Enter`; признак входа — из описания окружения.

Каждое «Тогда» — одна проверка, одной-двумя командами:
- элемент/текст/URL — `evaluate_script '() => …' --pageId 2 --waitForStableDom false`, вернуть
  только значение (`document.querySelector(sel)?.textContent`, `location.pathname`, число элементов);
- запросы — `list_network_requests 2 --resourceTypes fetch --resourceTypes xhr | grep '/api/search/'`;
  статус стоит в квадратных скобках (`[200]`), считать `grep -c '\[200\]'` и `grep -Ec '\[(4|5)[0-9]{2}\]'`;
- консоль — `list_console_messages 2 --types error`; пусто → ✅, иначе ❌ с первой строкой ошибки;
- действие «Когда» — `take_snapshot 2` ради `uid`, затем `click`/`type_text`; после действия
  проверки заново.
Критерии провала по умолчанию (если сценарий не задал иные): ошибка в консоли, ответ 4xx/5xx на
`/api/`, отсутствующий элемент. При ❌ — `take_screenshot 2 --filePath /tmp/devflow-smoke/<slug>/<n>-<имя>.png`.
Ошибка команды посреди прогона — ❌ у текущей проверки с текстом ошибки, остальные проверки
продолжить; `stop` в конце в любом случае.

## 5. Закрепление (`save`)
После прогона записать `<vault>/notes/smoke-<slug>.sh` (vault — из frontmatter `AGENTS.md`; файл
перезаписывается целиком) и назвать путь в разделе «Скрипт» ответа. Скрипт — только фактически
сработавшие вызовы обёртки, секреты — `@env:ИМЯ`, без `npx` и `mcp__`, вход — теми же командами
перед проверками. Каркас:
```bash
#!/usr/bin/env bash
# smoke-<slug> · env <имя> · <адрес> · <дата>
set -uo pipefail
S=$(devflow-browser start [--insecure] 2>/dev/null) || { echo "❌ start — devflow-browser не запустился"; exit 1; }
trap 'devflow-browser "$S" stop >/dev/null 2>&1' EXIT
fail=0
b() { devflow-browser "$S" "$@" 2>/dev/null; }
check() { if [[ "$2" == 1 ]]; then echo "✅ $1 — $3"; else echo "❌ $1 — $3"; fail=1; fi; }

b new_page "<адрес>" >/dev/null
n=$(b list_network_requests 2 --resourceTypes fetch --resourceTypes xhr | grep '/api/search/' | grep -c '\[200\]')
check "/api/search/* 200" "$(( n > 0 ))" "$n запросов [200]"
exit $fail
```
Каждое «Тогда» — одно `check`: значение из `evaluate_script … | tail -1` или счётчик `grep -c`,
условие — арифметика `$(( … ))` или `[[ … ]] && echo 1 || echo 0`. Действия «Когда» — через
`evaluate_script '() => document.querySelector("<sel>").click()'`, не по `uid` снимка (он
меняется между прогонами). Вывод навигации и `stderr` подавлены: на экране только строки
`✅ …`/`❌ …`, код выхода 0, если все ✅, иначе 1. Без `slug:` скрипт не пишется — «не хватает slug».

## Заметки
- Каждый вызов обёртки ≈2 с (`npx`); сценарий на 20 действий — около минуты. Не дробить проверки
  на лишние команды и не звать `take_snapshot` без нужды.
- Предупреждения Google о телеметрии в stderr `start` — шум, не ошибка.
- В pi скилла нет (`skip pi smoke`): там implement гоняет готовый `smoke-<slug>.sh`.
