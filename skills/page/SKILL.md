# /page — объяснительная HTML-страница

Одна дизайн-система на все страницы всех проектов. Скилл носит настоящий CSS, а не пересказ:
`references/tokens.css` — единственный источник правды по цвету и типографике.

**Дизайн-систему не изобретать.** Встроенный `artifact-design` сам велит сперва искать
существующую систему проекта — это она и есть, и она его переопределяет по палитре и
типографике. Механику тем, CSP и общие принципы оставляем ему.

## Когда применять

Когда прозы недостаточно: поток данных, зависимости модулей, машина состояний,
сравнение вариантов, отчёт с числами. И отдельно — когда пользователь говорит, что
разговор трудно воспринимать.

Не применять ради «покрасивее»: страница стоит дороже абзаца и живёт дольше.

## Процесс

### 1. Контекст проекта

Прочитать `AGENTS.md` из cwd — `project`, `vault`. Страницы кладутся в `<vault>/pages/`;
каталог создать, если его нет. Словарь предметной области берётся из `AGENTS.md` проекта:
на странице только его термины.

### 2. Определить вопрос страницы

Одно предложение: на какой вопрос страница отвечает. Оно же становится `h1`.
Если сформулировать не выходит — страница пока не нужна, нужен разговор.

### 3. Выбрать носитель для каждой схемы

Графовые связи (поток, зависимости, состояния, последовательность) — **mermaid**.
Редакторская картинка (массы, разрез слоёв, шкала, до/после) — **руками**, div с токенами
или инлайновый SVG. Разбор в [components.md](references/components.md).

### 4. Собрать файл

Скопировать [template.html](references/template.html), **вклеить в `<style>` целиком**
[tokens.css](references/tokens.css), дальше писать содержимое.

Жёсткие требования к файлу:

- **Самодостаточен.** Токены вклеены, а не подключены через `<link>`. Иначе он не переживёт
  ни CSP артефакта, ни копирование в другое место.
- **Начинается с `<!doctype html>` и не содержит `<html>`/`<head>`/`<body>`.** Локально это
  даёт standards mode, в артефакте одинокий doctype в теле парсер игнорирует. Один файл
  работает в обоих местах; **второго варианта не заводить**.
- **Три блока темы** из tokens.css сохранены все три, иначе переключатель темы на артефакте
  не переборет media-query.
- Предметные цвета — только в слотах `--s1 --s2 --s3` в `<style>` страницы. Систему не трогать.

Имя файла: `<vault>/pages/<slug>.html`, slug латиницей в kebab-case, для задачи — с ключом
(`se-2023-dataflow`). Содержимое — по-русски, как и заметки вольта.

### 5. Показать локально

```bash
explorer.exe "$(wslpath -w <vault>/pages/<slug>.html)"
```

`/mnt/f` — реальный диск `F:`, сервер не нужен. Сказать пользователю путь.

**Только `explorer.exe` с `wslpath -w`.** `wslview` строит путь через `\\wsl$\Ubuntu\mnt\f\…`
и упирается в Access is denied — он не знает, что `/mnt/f` это `F:`.

### 6. Артефакт — только по явной просьбе

Публикация имеет цену: страница уезжает наружу. По умолчанию файл остаётся локальным.
Когда просят — прочитать `artifact-design`, затем опубликовать тот же файл без изменений.
Mermaid в артефакте рендерится нативно, загрузчик из шаблона сам ничего не делает.

## Проверка перед сдачей

- [ ] Открывается двойным кликом из Windows, шрифты и схемы на месте
- [ ] Светлая и тёмная темы обе живые, ни один цвет не задан мимо токенов
- [ ] Каждая схема понятна без абзаца пояснений
- [ ] Легенда есть везде, где цветов больше одного
- [ ] Ни одной похвалы вне словаря («чище», «гибче», «легче поддерживать»)
- [ ] Таблицы и широкие схемы скроллятся внутри себя, страница по горизонтали — нет

## Правила

- **Один источник правды.** Правка палитры или типографики идёт в `references/tokens.css`,
  а не в отдельную страницу. Страницы, собранные раньше, при этом не перерисовываются задним
  числом — расхождение здесь допустимо и осознанно.
- **Mermaid грузится с CDN только локально.** Версия задана диапазоном `mermaid@11`; если
  понадобится воспроизводимость — прибить точную. Без сети схемы исчезнут, текст останется.
- **Не публиковать артефакт молча.** Это внешнее действие, оно за пользователем.
