# /xreview — второе мнение от Codex

Codex CLI установлен и залогинен **по подписке ChatGPT** (`auth_mode = chatgpt`, `OPENAI_API_KEY`
пуст). Запросы расходуют лимиты Plus/Pro, а не биллинг API.

Официального MCP-сервера «ChatGPT» не существует: коннекторы OpenAI работают в обратную сторону
(ChatGPT ходит в чужие MCP-серверы). `codex mcp-server` есть и подключается одной строкой, **но
подключать его не нужно** — постоянный коннектор стоит сотни токенов в преамбуле каждого запроса
всех сессий, а кросс-ревью нужно раз в несколько задач. Звать из Bash.

## 1. Проверить логин

```bash
codex login status     # ожидаем «Logged in using ChatGPT»
```

Если разлогинен — попросить пользователя выполнить `! codex login`, самому в браузерный вход не лезть.

## 2. Выбрать цель

Корень `green/` — не репозиторий; репозитории лежат подкаталогами (`meshnordic-search`,
`meshnordic-search-integrations`, `wordpress-app`, `shopify-apps`, `wordpress-local`). Сначала найти,
где вообще есть что смотреть:

```bash
cd /home/smg25/projects/resolventa/green
for d in */; do [ -d "$d/.git" ] && printf "%-35s %-20s dirty=%s ahead=%s\n" "$d" \
  "$(git -C "$d" rev-parse --abbrev-ref HEAD)" \
  "$(git -C "$d" status --porcelain | wc -l)" \
  "$(git -C "$d" rev-list --count main..HEAD 2>/dev/null)"; done
```

База — **локальный `main`**, не `origin/main`: `git fetch` в песочнице заблокирован, ветки
отводятся от локальной копии.

## 3. Прогнать

`codex review` печатает в stdout **весь diff целиком** перед вердиктом. Читать его через `tail`
нельзя — на тысяче строк вердикт не поместится. Всегда в файл:

```bash
OUT=<scratchpad>/xreview-<slug>.md
cd <repo>
codex review --base main --title "<SE-xxxx описание>" "<focus, если задан>" </dev/null > "$OUT" 2>&1
sed -n '/^codex$/,$p' "$OUT"        # только финальный вердикт
```

Флаги: `--base <branch>`, `--uncommitted` (staged + unstaged + untracked), `--commit <sha>`,
`--title`. Свободный промпт идёт первым позиционным аргументом. `</dev/null` обязателен — иначе
неожиданный запрос подтверждения повесит вызов до таймаута.

Прогон занимает минуты; ставить таймаут 600000 мс.

## 4. Прочитать вывод трезво

- **Тесты Codex не запустит.** PHP и node живут в контейнере, на хосте их нет — в вердикте будет
  «tests could not be run». Это ожидаемо, не считать провалом и не просить его гонять тесты.
- Вердикт «no actionable regressions» на статическом чтении — слабый сигнал, а не зелёный свет.
- Каждую находку **проверить в коде самому**, прежде чем править. Другая модель ошибается так же
  охотно, как своя; расхождение с собственным `/code-review` разбирать по существу, а не по
  авторитету.

## 5. Куда девать результат

Сырой дамп остаётся в scratchpad и умирает с сессией. Подтверждённые находки — в досье задачи через
`/note`, а не пересказом в чат.

## Чего не делать

- Не подключать `codex mcp-server` как MCP-коннектор.
- Не подменять этим `/code-review` — это второе мнение поверх своего, не замена.
- Не коммитить правки «потому что Codex сказал»: сначала подтверждение в коде.
