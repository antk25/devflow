# /xreview — второе мнение от Codex

Один протокол для Claude Code и pi: Codex CLI через Bash, не Claude и не MCP.
Не передавай Codex свои находки или результаты /review: это независимое мнение.

## 1. Контекст и цель

Запусти `devflow context`, прочитай `AGENTS.md` из cwd. Репозиторий — текущий cwd,
база — `Base branch` из AGENTS.md, не зашитый main. Если база не указана — уточни.
Не выполняй fetch. Зафиксируй HEAD, базу и цель до запроса:
- без цели — текущая ветка против локальной базы;
- ветка — её diff против базы;
- SHA — только этот коммит;
- диапазон — ровно `git diff <range>`;
- `--uncommitted` — staged + unstaged + untracked.
Неоднозначную цель уточни. Focus ограничивает вопрос, но не меняет выбранный diff.

## 2. Доступность

```bash
codex login status
```

Нет бинаря, авторизации или лимита — явно «второе мнение не получено», не «чисто».
При отсутствии авторизации предложи пользователю `! codex login`; сам вход не выполняй.
Не переключайся на Claude из pi.

## 3. Запуск

Сохрани входы и полный stdout/stderr в отдельный временный каталог вне репозитория.
Закрой stdin, поставь таймаут 600 секунд. Не обрезай вывод через tail: вердикт можно потерять.
Для текущей ветки, SHA и незакоммиченных правок соответственно:

```bash
codex review --base <base> </dev/null > <tmp>/xreview.out 2>&1
codex review --commit <sha> </dev/null > <tmp>/xreview.out 2>&1
codex review --uncommitted </dev/null > <tmp>/xreview.out 2>&1
```

Это альтернативы, не три последовательных ревью. Не сочетай позиционный prompt с
`--base`/`--commit`/`--uncommitted`: некоторые версии CLI запрещают это.
Для произвольной ветки, диапазона или focus подготовь `<tmp>/request.md` с точной целью,
инструкцией только читать, командой получения diff и вопросом, без собственных находок.
Запусти `codex review "$(< <tmp>/request.md)" </dev/null > <tmp>/xreview.out 2>&1`.
Не переключай рабочую ветку ради ревью.

Проверь код выхода, прочитай сохранённый файл через read. Отсутствие вердикта, timeout,
сигнал или exit≠0 — незавершённый обзор, даже если часть текста похожа на успех.
Не заявляй, что Codex запускал тесты: учитывай только фактические свидетельства в отчёте.

## 4. Проверка и результат

Каждую находку проверь в коде и выбранном diff: подтверждена / опровергнута / не проверить
(с причиной). Статическое «no actionable regressions» — слабый сигнал, не зелёный свет.
Покажи проверенные находки и ограничения. При наличии slug сохрани подтверждённые находки
в `<vault>/notes/<slug>-xreview.md`, сырой вывод оставь во временном каталоге.
Не подменяй этим /review; не исправляй код и не коммить по одному мнению Codex.

## Только чтение

До и после сравни `git status --porcelain=v1 --untracked-files=all`, `git diff HEAD --binary`
и содержимое untracked-файлов. Изменение дерева — нарушение; чужие правки не откатывай.
Действует политика инструментов; Bash не даёт гарантии изоляции ОС.
