# /cut — разрез сессии

Сессия перечитывает весь накопленный контекст на каждом запросе, поэтому её стоимость растёт как
квадрат длины. Этот скилл закрывает сессию так, чтобы следующая начала с чистой преамбулы и
ничего не потеряла.

**Правило дешевизны: не читать файлы.** Скилл запускается на 180K контекста — каждое лишнее
чтение оплачивается по полной. Всё, что нужно для передачи, уже в этой сессии. Единственное
исключение — `git log --oneline` и `git status` за факты о коммитах и незакоммиченном.

## Шаг 1. Определить задачу

Слаг из аргумента; иначе — из имени ветки, из последнего плана, о котором шла речь, или из
названия сессии. Если задачи нет вовсе (разведочная сессия без тикета) — слаг по теме,
например `analiz-sessij`.

Vault обычно уже в контексте — его кладёт SessionStart-хук (`PROJECT_RESTORE` / `OBSIDIAN_CONTEXT`).
Читать ради него `AGENTS.md` не нужно; читать только если хука в этой сессии не было.

## Шаг 2. Собрать факты о состоянии

Одной командой, без разбора файлов:

```bash
git -C <repo> log --oneline -12 && git -C <repo> status --short && git -C <repo> branch --show-current
```

Для монорепы — по каждой затронутой репе. Больше ничего не запускать: тесты, линтеры и сборки
на этом шаге не нужны, их результат уже известен из сессии.

Если сессия не трогала репозиторий (настройка харнеса, разбор, переписка с заказчиком) — команду
всё равно выполнить один раз: ветка и незакоммиченное это состояние среды, которое надо передать.
Раздел «Сделано» тогда перечисляет изменённые файлы, а не коммиты.

## Шаг 3. Записать передачу

Файл: `<vault>/notes/handoff-<slug>.md`. **Один файл на задачу, перезаписывается на каждом
разрезе** — это снимок «где я сейчас», а не журнал. Журнал — это `changelog/`.

```markdown
---
created: YYYY-MM-DD
project: <project>
type: handoff
task: <SE-XXXX или слаг>
tags: [передача, <задача>]
---

# <Задача> — передача <YYYY-MM-DD HH:MM>

## Где остановились
Фаза (research / plan / implement / ревью), шаг плана, ветка.

## Сделано
Коммиты хэшем и сообщением; пройденные шаги плана. Только факты.

## Следующий шаг
Одно конкретное действие с файлом и строкой. Не «доделать импорт», а
«`WooAttributeService.php:88` — заменить `foreach` по промису на `Utils::settle`».

## Решения этой сессии, которых нет в плане
Самое ценное в документе. Всё, о чём договорились или что выяснили по ходу и что не попало
ни в план, ни в тикет.

## Тупики
Что проверено и не сработало, с причиной. Без этого следующая сессия повторит работу —
именно это теряет автоматическая сводка.

## Состояние среды
Незакоммиченное, поднятые контейнеры, залитые дампы, открытые вкладки браузера, применённые
временные правки, которые надо откатить.
```

Пустые разделы удалять, а не заполнять словом «нет».

## Шаг 4. Выдать строку продолжения

Последним сообщением — готовый к вставке текст и ничего больше:

```
Продолжаем <SE-XXXX>. Прочитай <vault>/notes/handoff-<slug>.md и продолжай
со «Следующего шага».
```

И одна строка: «Записал. Теперь `/clear`, потом вставь это.»

## Чего не делать

- **Не коммитить и не пушить.** Разрез — это про контекст, а не про публикацию. Если есть
  незакоммиченное, оно описывается в «Состоянии среды», и решение принимает пользователь.
- **Не пересказывать сессию.** Передача — это состояние, а не протокол. Если тянет на две
  страницы, значит, пишется журнал, а он в `changelog/`.
- **Не вызывать `/clear` самому** — это делает пользователь.
