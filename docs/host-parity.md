## Оставшиеся действия пользователя и следующего прогона

Все действия — в отдельном локальном учебном git-проекте с маленькой функцией и тестом, своим vault и `AGENTS.md` (`project`, `vault`, Browser/local на http://127.0.0.1:18765, вход: нет). Существующий стенд не запускать и не останавливать.

1. Зарегистрировать учебный проект через `/project`, затем открыть его в Claude Code самостоятельно. Выполнить `/devflow <учебный-slug>`; отдельно ответить на research- и plan-гейтах. До каждого ответа проверить `devflow route <учебный-slug>`: `approval_required`. Завершить implement и crossreview, сохранить ревизии, run_id и выводы.
2. Повторить отдельный цикл через `devflow-pi <учебный-проект> --model openai-codex/gpt-6.1-sol:low`; каждый дочерний процесс запускать с той же моделью явным `--model`. Не менять глобальную policy ради приёмки.
3. Прервать implement в Claude, открыть pi, выполнить `devflow status <slug>`, `devflow interrupt <run-id> --reason 'учебная смена хоста'`, затем `devflow resume <slug> --reason 'явное восстановление'`. Проверить сохранение approvals и истории; повторить в обратном направлении, Claude открывает пользователь. Не запускать повторно running.
4. В подготовленном проекте вызвать новый `/smoke slug: <учебный-slug>; env: local; save; …`, проверить кнопку «Проверить», ответ `/api/check` 200 и «Готово». Запустить сохранённый скрипт, записать код выхода и вывод; повторить в штатном режиме управляемой ошибки стенда и доказать остановку Chrome после обоих исходов. Секреты только через `@env`.
5. Отдельно доказать настоящий Codex и запасной pi-процесс second-opinion (без первого списка находок); безопасно смоделировать отказ Codex. Сохранить фактические модели, отчёты и коды выхода. Одних автоматических тестов недостаточно.

После устранения препятствий повторить browser-приёмку; не объявлять шаг done до получения доказательств. Полный набор отслеживаемой версии уже зелёный в изолированной копии; не повторять чтение пользовательского combos ради этого критерия. Поле фиктивного секрета не требуется стенду: в следующем задании можно явно оставить его пустым либо заранее согласовать настройку ссылки `@env` без изменения пользовательских секретов агентом.
